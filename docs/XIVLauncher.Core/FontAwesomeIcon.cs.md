## 1. Purpose

Maps every Font Awesome 5 (version `5.0.9`, per the file's leading comment) icon name to the **Private Use Area code point** that selects the corresponding glyph. Combined with `IconFont` (loaded by `FontManager` from `FontAwesome5FreeSolid.otf`), an enum member is a complete "draw this icon" token.

The file is machine-generated/curated data, not logic: 1,408 enum members (1,407 icons + `None = 0`), each carrying its own doc comment (`The Font Awesome "name" icon unicode character.`), plus a two-method extension class.

## 4. `FontAwesomeExtensions`

```csharp
public static char   ToIconChar (this FontAwesomeIcon icon) => (char)icon;
public static string ToIconString(this FontAwesomeIcon icon) => string.Empty + (char)icon;
```

- `this FontAwesomeIcon icon` is C# 13's explicit-parameter ("this parameter") syntax. Because the first parameter is `this`-annotated with the enum type, both helpers are **extension members of an enum value**: `FontAwesomeIcon.Cog.ToIconString()` resolves to `FontAwesomeExtensions.ToIconString(FontAwesomeIcon.Cog)`. The hosting class name never appears at call sites; removing the `this` annotation would break every `Components/*` call site.
- `char` is a UTF-16 code unit; all values here are in the BMP (`≤ 0xF957`), so one `char` per icon is sufficient — no surrogate pairs, and no `String.Concat` of two code units is required.
- `string.Empty + (char)icon` is a `String + char` concatenation (allocates via `operator+`), i.e. `ToIconString` is not `const`-foldable. Prefer embedding the `char` into a larger `string` literal at the call site if it is per-frame text.
- ImGui text calls take UTF-8 byte pointers in the Hexa binding, so both helpers are consumed by the binding's C#→UTF-8 marshalling, not by raw pointer passing.

## 5. Contract and caveats

- **`None = 0` is a sentinel, not a glyph.** `ToIconChar(None)` yields `'\0'`; rendering it is undefined for ImGui/SDL (a NUL byte terminates the string in the native call). Filter it before drawing.
- **Range mismatch with `FontManager`:** `FontManager` loads the icon font with glyph range `0xE000–0xF8FF`, but 10 members fall at `0xF900–0xF957` and are therefore **not rasterised**: `FirefoxBrowser (0xF907)`, `Ideal (0xF913)`, `Microblog (0xF91A)`, `PiedPiperSquare (0xF91E)`, `Trailer (0xF941)`, `Unity (0xF949)`, `Dailymotion (0xF952)`, `InstagramSquare (0xF955)`, `Mixer (0xF956)`, `Shopify (0xF957)`. If used in the UI they show as the missing-glyph box. Either extend the range to `0xF9FF` in `FontManager` or avoid these ten names.
- **Style availability is not encoded.** The enum covers the full FA 5 name space (including brand names such as `Youtube`, `Facebook`-style entries); the embedded font is `FontAwesome5FreeSolid.otf`, i.e. the *free* set. An enum member may exist with no glyph in that file; nothing here indicates which names are solid-only or missing. Treat icon presence as "verify visually" rather than "assume from the name list".
- **Enum members are compile-time constants**, so they are usable in `case` labels and constant contexts; the values are implicit `int`s — passing them where `char`/`ImWchar` is required needs an explicit cast (the helpers exist for that).
- The enum is not `sealed` and, being an enum, cannot be extended at all: adding an icon means editing this data file (or the generator that produced it).
- Adding an icon requires updating only the enum **and** the font: the glyph must exist in `FontAwesome5FreeSolid.otf` inside the loaded range.
- The file carries no `// <auto-generated />` marker despite being generated data; regenerate from the FA 5 metadata with the same naming rules if regenerated, otherwise `git`-diffs churn.

## 6. Typical use

```csharp
ImGui.PushFont(FontManager.IconFont, 0.0f);
if (ImGui.Button(FontAwesomeIcon.Cog.ToIconString(), btnSize)) { /* ... */ }
ImGui.PushFont(FontManager.TextFont, 0.0f); // restore the text face afterwards
```

This is the idiom used throughout `Components/*` (`ActionButtons.cs`, `LoginFrame.cs`, `SettingsPage.cs`, `OtpEntryPage.cs`): the icon face is pushed explicitly, one glyph per button label, and `TextFont` is pushed back afterwards — there is no `PopFont` pairing in those call sites, so font state is set by push-on-push-off convention.

Related units: `FontManager.cs` (`IconFont`, `0xE000–0xF8FF` range), `AppUtil.cs` (embeds the `.otf`), `Components/*` (icon usage; out of scope for this pass).
